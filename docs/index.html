TL;DR
  • JPEG first, neural second. Encode with JPEG at quality 1, then let a small learned codec encode only the residual (original minus decoded JPEG).
  • Backward compatible. The JPEG part is a standard file; any viewer can show it without the neural decoder.
  • Small and quick. 10.14M parameters, a two-pass checkerboard entropy model, and about 0.76 s per Kodak image on one GPU.
  • Honest numbers. Results below are re-measured from real bitstreams. Doing so exposed three codec bugs, which are fixed and documented.
Method

Compress what JPEG gets wrong

Standard codecs are fast and everywhere but fall apart at low bitrates. Learned codecs look far better but are big and slow. HyRES keeps JPEG as the base layer and spends neural effort only on the error.

What the residual looks like

At quality 1, JPEG keeps coarse 8×8 block averages and drops almost all detail and color. The residual holds everything else: edges, texture and color shifts. The codec has to reproduce it, not the whole image.

Residual codec

Training: start sharp, then trade bits away

The loss is the usual rate-distortion objective, bpp + λ·MSE. Early runs at three λ values confirmed the trade-off (higher λ, more bits, lower MSE). So training was split into six phases: a high λ first, so the model learns to reconstruct, then λ lowered step by step, each phase starting from the previous best checkpoint. Data: Mini-ImageNet (60k images, 7 GB), on a single A40.

Reproducibility

What re-measuring found

During the project, every number came from the model's training-time estimate. When we later decoded real bitstreams with the surviving weights, three bugs showed up. All are fixed in the repository, and none needs retraining.

1. Clamped residual

The decoder clamped the residual to [0, 1]. Residuals are signed, so every negative correction was lost.

24.46 → 37.41 dB

2. Coding empty positions

Each checkerboard pass coded the full tensor, including the other half's empty positions. Each pass now codes only its own positions.

1.878 → 1.563 bpp

3. Optimistic rate estimate

Training scored each latent with the sum of both passes' parameters, a distribution no decoder has. It now uses the same parameters as the coder, giving a slight over-estimate (1.67 bpp).

est. 1.279 vs real 1.563 bpp

Bug 3 also means every model trained so far optimized the wrong rate term. Retraining with the fixed estimate should move the whole curve, which makes it the most promising next step.

Limitations

  • Only the Phase 1 weights survive, so phases 2 to 6 cannot be re-measured.
  • Kodak was also used to pick checkpoints during training, so it is not a fully held-out test set.
  • MSE-only training: reconstructions are smooth rather than perceptually sharp.
  • Image sides must be multiples of 32. Inference runs on CUDA or CPU, not Apple MPS.
Project history

How it got here

  1. Feb 2025
    Proposal. A content-aware hybrid codec: JPEG base plus a residual coded only in important regions, chosen by a learned importance map.
  2. Mar 2025
    Design. Survey of learned compression from 2018 to 2023. The importance map was dropped for a lightweight codec built for residuals: GDN, residual bottlenecks, attention, checkerboard context.
  3. Apr 2025
    First training runs. Three λ and JPEG-quality settings confirmed the rate-distortion trade-off and led to the multi-phase schedule.
  4. May 2025
    Six phases and refinement. λ from 0.045 down to 0.002, then a refinement network trained on the frozen final model.
  5. Oct 2026
    Re-measurement. Real-bitstream evaluation of the surviving weights, three codec fixes, and this page.
